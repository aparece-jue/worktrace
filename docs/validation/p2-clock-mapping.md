# P2 开工前：单调 / 墙钟映射实测记录

06 §4 把「单调/墙钟映射」列为**实现前**技术验证，结论会反过来决定 P2 的异常阈值与
状态机（总纲 §5 第 9 条）。本文是该实验的记录，探针在
`src-tauri/examples/clock_probe.rs`。

**探针不改系统时间。** 锁屏、休眠、正反改时全部由人工操作；操作前按一次回车打标记，
汇总里就能把人为干预与自然漂移分开。

## 2. 判定口径（08 §1，P2 Task 2）

- 阈值 `THRESHOLD_MS = 2000`，**严格大于**才越界；恰好 2000ms 不算。
- **两个差都要看**，任一越界即进入异常判断：
  - **相邻增量差** `d_wall - d_mono`：这一拍两个时钟走得是否一样快；
  - **累计偏差** `(wall - wall₀) - (mono - mono₀)`：从起点算总共差了多少。
- 只看相邻增量会漏掉**缓慢累计漂移**（每次几十毫秒、单次永不越界，但累计会越界）。
  这一条由单元测试 `slow_cumulative_drift_is_caught_even_though_each_step_is_small` 钉住。
- 单调钟**倒退**是硬故障（正常平台永不出现）；挂钟倒退是正常的用户行为。

## 3. 自然漂移基线（无人工干预）

命令：`cargo run --example clock_probe -- --seconds 60 --interval-ms 1000`

| 指标 | 值 |
| --- | --- |
| 采样数 | 60（1 秒间隔，共 60 秒） |
| 采样失败 | 0 |
| 越界（>2000ms） | 0 |
| 相邻增量差最大值 | **1 ms** |
| 累计偏差最大值 | **14 ms** |
| 挂钟倒退次数 | 0 |
| 单调钟倒退次数 | 0 |
| 间隔偏离最大值 | 1 ms |
| 疑似挂起次数 | 0 |

明细片段（每行 `idx,wall_ms,monotonic_ms,d_wall,d_mono,delta_gap,cum_gap,flag`）：

```text
56,1791009059287,56021,1001,1000,1,13,
57,1791009060287,57021,1000,1000,0,13,
58,1791009061288,58022,1001,1001,0,13,
59,1791009062289,59022,1001,1000,1,14,
60,1791009063289,60022,1000,1000,0,14,
```

### ⚠ 这台机器上发现的关键数字：累计偏差按 ~10–14ms/分钟增长

相邻增量差始终是 0 或 ±1ms（两个时钟**每一拍都同步**），但**累计偏差**单向增长。
三次独立时长的实测：

| 时长 | 采样数 | 累计偏差 | 相邻增量差最大 | 折算速率 |
| --- | --- | --- | --- | --- |
| 60 s | 60 | 14 ms | 1 ms | **14.0** ms/min |
| 300 s | 300 | 70 ms | 1 ms | **14.0** ms/min |
| 600 s | 600 | 100 ms | 1 ms | **10.0** ms/min |

**速率不是常数**：第三次观察到的增长速率较低。采样证明这台机器上两个时钟存在相对走时差，但没有记录时间服务状态，不能据此确认差异由 NTP 校准造成，也不能将这个速率推广到其它机器。

按观察到的 10～14ms/min 外推，固定 2000ms 的运行期累计偏差界可能在约 2.4～3.3 小时后误报。因此当前设计保留短期参照，并为独立长期参照增加初始自然漂移容差；归属基线不随心跳移动。

### 分辨率观察与设计结论

探针以最快速度连读两万个样本，得到：

```text
wall_systemtime:   samples=20000  min_positive_ns=100  max_ns=4200  zero_permille=642
                   distinct_deltas=[0, 100, 200, 300, 800, 900]
monotonic_instant: samples=20000  min_positive_ns=100  max_ns=8400  zero_permille=663
                   distinct_deltas=[0, 100, 200, 300, 800, 900]
```

两个读取路径均观察到 100ns 的最小正增量，未见原先猜测的 15.6ms 粗粒度。该记录支持相对走时差的观察；它不单独证明硬件时钟误差或时间服务校准的具体成因。

早期方案曾建议“每次成功心跳前移锚点”，此方案已被三参照点设计替代。当前口径为：

- **归属 anchor / A(M)**：连续可信运行期间固定；旧开放事实闭合或隔离后才允许重建。
- **短期 drift_ref**：成功心跳后移动，偏差严格大于 2000ms 触发异常判断。
- **长期 lifetime_ref / L(M)**：不随心跳或普通暂停重置，边界为 2000ms + floor((M-lifetime_monotonic_at)×500/1_000_000)；仅新 run 初始化或已检测墙钟异常的审计提交后移动。

500 ppm 是初始策略，需跨机器校准。短期记录中没有异常，不等于任意长会话都已通过实机验证；四小时自然漂移场景的自动回归与正式平台验收分别登记。

## 4. 人工操作

### 结果

**4.2 休眠/唤醒：已有本机采样记录（实际实验日期待核实）**

原标注日期为 2026-10-04，晚于本轮评审日期。未找到独立的带日期原始日志，不能直接改成推测日期；保留下面的采样值，实验日期待核实。

命令 `--seconds 300 --interval-ms 1000`，第 10 拍打 `sleep` 标记后立刻休眠约 2 分钟再唤醒。

```text
idx=25  wall=1791010741354  mono=25010   d_wall=1000     d_mono=1001     gap=-1   cum=2
idx=26  wall=1791010870439  mono=154131  d_wall=129085   d_mono=129121   gap=-36  cum=-34   SUSPECT_SUSPEND
idx=27  wall=1791010871505  mono=155197  d_wall=1066     d_mono=1066     gap=0    cum=-34
```

| 观测 | 值 |
| --- | --- |
| 休眠时长（按**单调钟**） | **129121 ms** = 129.1 s |
| 休眠时长（按**挂钟**） | 129085 ms = 129.1 s |
| 两者之差（Δgap） | **−36 ms** |
| 若 QPC 在休眠期间停走，`d_mono` 应为 | ≈ 1000 ms |
| 实测 `d_mono` | **129121 ms** —— 与「停走」相差 128 秒 |

**结论：QPC（单调钟）在休眠期间照常推进，两个时钟没有错位。**

这一条推翻了我原先担心的另一种可能——「QPC 停走会让墙钟与单调钟永久错位 2 分钟」。
实测没有发生，所以：

- **休眠不是时钟分叉事件**，`delta_gap` 只有 −36ms，与正常漂移同量级。
- 它表现为**一拍的单调增量特别大**（`looks_suspended` 按预期触发 `SUSPECT_SUSPEND`），
  即「一段很长的间隔」，而不是「两个时钟对不上」。
- ⇒ **可信离开边界按策略 pause；无可靠边界则 recovering**，不能仅由两个时钟同步判断（P2 Task 2 原文），
  并在恢复后重建基线。现在这条有实测支撑了。
- 另注：`cum_gap` 从 +2 变成 −34，表明两钟累计偏差变化了 −36ms；未记录时间服务状态，不能确认是否由 NTP 校准造成。

**4.3 / 4.4 正反改时：未实测，仍待验证。** 时钟独立是实现依据，不能替代对本机操作、异常检测与事件通知的实测。FakeClock 仅验证逻辑。

**4.1 锁屏 30 分钟：未实测，仍待验证。** 休眠实验不能替代锁屏策略、通知时点及其延迟的验证。正式接线与实机验收仍保留在 P7/P8。

**4.5 关窗静置：不适用**

探针是前台进程，关不关窗对它没有影响。它证明不了「关窗后仍在采样」——那要等 P7
建立的周期采样驱动。保留本行只作对照。

## 5. 修订后的阈值策略

- 相邻增量差、最近成功心跳参照点的偏差，严格大于 2000ms 才进入恢复判断。
- 归属基线固定，短期检测参照点可以随心跳移动；长期边界 abs(wall-L(M)) > 2000ms + floor(elapsed_ms×500/1_000_000) 不随心跳清零。500 ppm 为初始版本化策略，不是普遍的平台结论。
- 两钟同步的长间隔不证明离开开始边界。可信平台边界 pause；边界未知、通知晚到则 recovering；唤醒不自动继续。
- 实测支持保留自然漂移容差，不支持取消正反改时、锁屏与正式事件通知验收。

## 6. 未验证项（**不要当成已验证**）

- 探针是**前台进程**，它证明不了「关窗后仍在采样」——那需要 P7 建立的周期采样驱动。
- 它也证明不了**系统事件（锁屏/休眠通知）的可靠性**与到达延迟；那属于 P7 的正式
  事件接线，由 P7 实测、P6 硬化、P8 最终验收。
- 本题结论只覆盖**这台机器 + 这个 Windows 版本**。换机器或换系统要重跑。
- `FakeClock` 的单元测试通过**不代表**实机行为已确认；两者分别登记状态。

## 7. 修订后的实施结论

原始采样记录保留。自然漂移与一次休眠结果可以支持 P2 核心实现，但不构成平台验收完成。

- 固定归属 anchor 不移动；短期检测参照点随成功心跳移动。追加长期边界 2000ms + floor(elapsed_ms×500/1_000_000)，阻止心跳隐藏累计异常。500 ppm 是初始策略，需后续不同机器实测校准。
- 两钟同步只说明没有明显时钟分叉，不能确定离开开始时刻。可信平台边界 pause；通知晚到或无可靠边界 recovering；醒来不自动计时。
- 锁屏、正反改时、关窗后台采样与事件可靠性/延迟仍待 P7/P8 实机验证，不能取消或用推理冒充完成。
- 本轮仅验证 P1/P2 核心，用户要求稳定前不推进后续阶段。

## 三参照点修订

长期边界使用独立参照 L(M)=lifetime_wall_at+(M-lifetime_monotonic_at)，abs(sampled_wall_at-L(M)) > 2000ms + floor((M-lifetime_monotonic_at)×500/1_000_000)。A(M) 仅用于工时归属，不作为长期偏差参照。三个参照分别为：归属 anchor（旧开放事实闭合/隔离后才可重建）、短期 drift_ref（成功心跳或归属重建时移动）、长期 lifetime_ref（新 run 初始化，或已检测墙钟偏移/漂移的审计提交后移动）。普通 pause/resume、可信系统离开边界、无可靠边界的长间隔、采样失败均不得移动长期参照；单调钟倒退不是墙钟校正，须隔离并由新 run 安全重建。

暂停/终结态遇墙钟异常时，先原子写 clock correction 审计并增加 revision，再接受新归属与长期参照；暂停会话版本递增，终结态不修改会话或历史区间。随后 resume 使用新版本，不会成功后立即再次恢复。此处“接受校正”仅表示承认新的时钟映射，不代表确认可疑工时。recovering 记录重复事件保持幂等；未接受的墙钟异常仍存在时拒绝 start/resume，而不是先返回成功。
