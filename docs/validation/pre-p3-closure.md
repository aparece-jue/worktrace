## P3 必须验证的异常闭环

| 情形 | 应有结果、恢复出口与验证 |
| --- | --- |
| 旧 epoch/旧版本同时出现时钟异常 | 请求预检先拒绝，用户命令零写入；独立采样仍能隔离异常，不能由旧请求触发写入。P3 新包装沿用总纲 §9 的字段级断言 |
| 长间隔/无基线/未知终点/可信前缀 | 无证据不猜时长；启动扫描规范化与 P2 实时异常不重复分割；reconcile/discard_uncertain 保留可信前缀，discard_session 作废整次。覆盖 NULL/零长度/非零候选及 CHECK、审计 |
| 已检测墙钟校正 | 未接受持续拒绝 start/resume；接受校正先提交审计再清内存标记，不自动确认待确认工时；reconcile 与接受校正独立测试 |
| 存储忙/磁盘不足使异常事务失败 | 事务完整回滚，协调器停止可信暂计并 faulted；S12 用户显式重试成功后重算门禁，失败不清故障；单调倒退仍需新 run，禁止用 S12 掩盖 |
| 数据库提交成功但重扫门禁失败 | 不宣称回滚，不重复执行用户意图；返回 RECOVERY_REQUIRED，停止业务计时、保留故障。恢复出口为显式重扫/重试成功或安全新 run；使用提交后权威版本刷新，P8 不自动重发写命令 |
| 四类扫描含不变量损坏 | 损坏隔离与待确认分开，可疑工时不进统计；整批扫描一次 revision/审计规则，重复扫描无重复分割；attention_overview 仍能发现旧会话问题 |
| 任务完成/取消/Waiting/Blocked 与计时同时发生 | 一把锁、同次采样、一次用户事务联动；recovering 拒绝、失败全回滚，原 finish 不冒充完成任务 |

P3 Task 7 逐行提供测试名/结果，P6/P8 消费同一故障与提示语义。对已经提交的事实，任何后置失败均不能标注“被拒所以零写入”；区分系统异常事务、用户事务与提交后收尾三个阶段。
