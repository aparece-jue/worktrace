## 1. V0.1 —— 建立底座

SPEC §51 的范围：Task、Project、Basic Tag、Timer、WorkSession、SQLite、Today、Inbox、Tray、Basic HUD。

### 1.1 任务核心

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-001 | Inbox 快速捕获 | 全局快捷键唤起输入框，输入一句话回车即创建任务；任务出现在 Inbox；**全过程不要求选择项目/标签/日期**；从唤起到任务可见 ≤ 3 秒 | M02 M12 | §3.1 §36 |
| F-002 | 任务理清 | 可从 Inbox 把任务移出并设为 Ready；可设下一步动作、所属项目、标签；理清过程不强制填任何字段 | M02 M12 | §3.1 |
| F-003 | 任务状态机 | 支持 Inbox / Clarifying / Ready / Scheduled / Doing / Blocked / Waiting / Review / Done / Cancelled 共 10 个状态；**非法跃迁被拒绝且不写库**；`Blocked` 与 `Waiting` 必须可分别选择 | M02 | §9 |
| F-004 | 项目管理 | 可创建、重命名、归档项目；任务可归属项目；归档项目不出现在新建任务的选择列表 | M01 M02 M12 | §8.2 |
| F-005 | 基础标签 | 可创建 Domain / Activity / Context / Report 四类标签并打标到任务；同一任务可有多个标签 | M01 M02 | §16 |

### 1.2 计时与工时

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-006 | 计时器（Stopwatch + Countdown） | 可正计时与倒计时；可暂停/恢复/结束；倒计时到点有可感知提示 | M04 | §14 |
| F-007 | 计时精度 | **系统休眠 30 分钟后恢复，显示值误差 ≤ 1 秒**；窗口隐藏、最小化到托盘期间计时继续 | M04 M00 | §15 |
| F-008 | WorkSession 分段计时 | 同一任务可分多次计时，每次为独立 session；任务实际工时 = 各 session 时长之和（扣除暂停） | M05 | §11 |
| F-009 | 计时与任务解耦 | 关闭主窗、关闭 HUD、最小化到托盘，计时均不中断；重开窗口后显示值与实际一致 | M04 M11 | §42 |

### 1.3 界面与外壳

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-010 | Today 页 | 显示：今日计划、当前任务、今日已工作、剩余任务；当前任务有明确视觉标识 | M06 M12 | §37 |
| F-011 | 托盘 | 提供当前任务、暂停、完成、快速捕获、显示 HUD、退出；**关闭所有窗口后托盘仍可用且计时继续** | M11 | §42 |
| F-012 | Basic HUD | 独立窗口，具备置顶 / 透明 / 鼠标穿透 / 不抢焦点 / 无任务栏图标五项；显示当前任务名与计时进度 | M11 M00 | §38 §40 |
| F-013 | HUD 模式切换 | 可在 Locked（穿透，不可交互）与 Edit（可拖动、可调整、可配置）之间切换；切换即时生效 | M11 M00 | §40 |

### 1.4 数据与可靠性

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-014 | 本地优先 | 全部数据存本地 SQLite；**拔网线后所有 V0.1 功能可用**，无任何报错或降级提示 | M01 | §5.1 |
| F-015 | 崩溃恢复 | 进程被强杀后重启：未结束的 session 被标记为待确认并出现在 UI 中；**系统不自动补写工时**；用户确认后才计入统计 | M01 M05 | §46 §57 |
| F-016 | 单实例 | 第二次启动唤起已有实例的主窗，不产生第二个进程；第二次启动不损坏数据库 | M00 | §42 |

## 2. V0.2 —— 知识与统计

SPEC §52 的范围：Knowledge Tag、Weighted Tag、Reports、TimeBlock、Pomodoro、Interruption、Multi Session。

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-101 | 并发任务 | 可同时运行多个 session；**至多一个 FOREGROUND**（尝试创建第二个时被拒绝并给出提示） | M05 | §12 |
| F-102 | 执行模式 | 每个 session 可选 FOREGROUND / BACKGROUND / PASSIVE / WAITING | M05 | §12 |
| F-103 | 人工工时口径 | **1h 前台设计 + 1h 后台 AI 生成，统计结果必须是 1h 人工工时**，不是 2h | M06 | §12 |
| F-104 | Pomodoro | 支持 25/5、50/10、90/20 与自定义；工作段与休息段可区分 | M04 | §14 |
| F-105 | TimeBlock | 可把任务排入时间段（如 14:00–15:30）；Today 页按时间块展示 | M04 M12 | §14 §37 |
| F-106 | 打断管理 | 计时中启动新任务 → 原 session 暂停并记录打断；可查询"本周被打断 N 次、损失 X 时长" | M05 M06 | §23 |
| F-107 | Knowledge 标签 | 可创建带层级的 Knowledge 标签（如 Electronics → Analog → ADC） | M01 M02 | §16.3 |
| F-108 | 标签权重 | 可为任务的标签设权重（如 Design 60% / Research 20% / Review 20%） | M01 M02 | §17 |
| F-109 | 两种工时统计 | **关联时长**（标签全额计入）与**加权工时**（按权重分配）分别可查，同一任务两种口径结果不同且都可解释 | M06 | §18 |
| F-110 | 搜索 | 跨任务 / 项目 / 文档 / 决策 / 知识 / 上下文 / 会话统一检索；结果按类型分组 | M13 | §47 |
| F-111 | 报表 | Daily / Weekly / Monthly / Quarterly / Custom 五种范围；按 Project / Goal / Domain / Activity / Knowledge / Report Tag / Task / Milestone 筛选 | M07 | §43 |
| F-112 | 导出 | 可导出 JSON / CSV / Markdown；导出文件内容与界面显示一致 | M07 | §45 |
| F-113 | 估时误差统计 | 可看到"某类任务平均低估 X%"这类结论；数据来自 estimated 与 actual 的差值 | M06 M08 | §22 |

## 3. V0.3 —— AI 辅助

SPEC §53。**全部条目的共同前提：AI 不可用时，V0.1/V0.2 功能不受任何影响，且不出现报错弹窗。**

| ID | 功能 | 验收标准 | 依赖 | SPEC |
| --- | --- | --- | --- | --- |
| F-201 | AI 任务澄清 | 对模糊任务（如"研究一下"）给出具体化建议；建议可一键采纳或忽略 | M10 | §3.4 §32 |
| F-202 | AI 任务拆解 | 对复杂任务给出子任务建议；用户可勾选采纳哪些 | M10 | §3.2 §32 |
| F-203 | AI 估时 | 给出预计时长**并带 confidence**；用户采纳后写入 `estimated_json` 且 `source = ai` | M10 M02 | §22 §33 |
| F-204 | AI 打标建议 | 建议 Domain / Activity / Knowledge 标签 | M10 | §32 |
| F-205 | AI 优先级建议 | 给出优先级建议，**不得覆盖任何 `source = user` 的既有值**；冲突时保留用户值并提示 | M10 M02 | §5.3 |
| F-206 | AI 质量统计 | 可看到估时误差、标签接受率、拆分接受率、优先级修改率 | M10 | §35 |
| F-207 | AI 反馈 | 可对建议快速反馈（太细/太粗/估时太长/太短/标签错/分类错/优先级不合理） | M10 | §34 |
| F-208 | 保密等级阻断 | 标记为 `STRICT_LOCAL` 的上下文**不会出现在任何外发请求中**；可用抓包或日志验证 | M09 M10 | §31 |

## 7. 全局非功能要求

| 项 | 要求 |
| --- | --- |
| 无网可用 | 除 V0.3+ 的 AI 功能外，全部功能离线可用且无报错 |
| 数据可迁移 | 至少支持 JSON / CSV / Markdown 导出；用户不被锁死在数据库内部（SPEC §45） |
| 数据可解释 | AI 输出尽量携带来源、置信度、修改记录（SPEC §57-3） |
| 管理成本 | 记录任务的操作步骤不得多于手动写在纸上（SPEC §57-1） |
| 长期优先 | 任何为"第一天看起来聪明"而牺牲长期可维护性的设计应予否决（SPEC §57-5） |

## 8. 不验收清单（Non-Goals）

以下明确**不写验收标准**，因为 SPEC §50 已把它们排除：插件市场、通用工作流引擎、通用 Agent 平台、完整 CAD 自动化、IDE 替代、Office 替代、通用自动化平台。
